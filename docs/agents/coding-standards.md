# Coding Standards

実装時に従うリポジトリ横断の規約。用語と Principles は [CONTEXT.md](../../CONTEXT.md)、ドメインモデルは [domain.md](./domain.md) を正とする。

## API contract と codegen (ADR 0010)

- クライアント向け REST API の形は `docs/spec/openapi.yaml` が single source of truth。エンドポイントの追加・変更は必ず openapi.yaml から始める。
- 生成コードは**手編集禁止**(ヘッダに autogenerated と書かれているファイル):
  - `backend/internal/api/gen.go` — oapi-codegen (strict-server + echo-server + models + embedded-spec)
  - `frontend/src/api/schema.d.ts` — openapi-typescript
- 再生成コマンド(生成物はコミットする):
  - backend: `cd backend && go generate ./...`
  - frontend: `cd frontend && npm run generate`
- spec と生成コードのドリフトは `scripts/check-codegen.sh` が検出する(CI の `codegen-and-db-test` job でも実行)。openapi.yaml を変更したら両側を再生成してからコミットすること。
- backend のハンドラは `StrictServerInterface` の実装として書く。リクエストの形式検証(422)は kin-openapi middleware が spec から自動で行うため、ハンドラ内に手書きの形式チェックを重複させない。

## DB スキーマと migration

- DB スキーマは `backend/internal/store/migrations/` の SQL ファイルが正。スキーマの Markdown ドキュメントは持たない(ドリフトするため)。
- migration は Bun の `migrate` パッケージで管理し、サーバー起動時に自動適用される。
- 新しい migration は `YYYYMMDDHHMMSS_<name>.up.sql` / `.down.sql` のペアで追加する。適用済み migration ファイルは編集しない。

## テスト (ADR 0012)

- PostgreSQL、Redis、実行中の backend、Ingress、frontend を必要とするテストは、k3s の隔離 namespace にKustomizeでデプロイし、公開 HTTP interface を通して観測する。テスト内で server を組み立てたり、testcontainers で依存を起動したりする第二の実行経路は作らない。
- 主要な正常系はKubernetes test Jobからbrowser E2Eで確認し、画面から到達しにくいAPI contractは同じJobから公開HTTP APIを直接検査する。テストデータは公開interface経由で作り、DBをassertion seamにしない。
- 外部依存なしで観測できる純粋なロジックだけを通常の unit test に残す。store は具象型のままとし、DB fake や repository interface を作らない(interface の方針は ADR 0011)。
- frontend のテストは vitest + happy-dom。fetch は `vi.stubGlobal('fetch', ...)` でスタブする(MSW は導入しない)。

## 色は token のみ (no-raw-colors)

- アプリコードで Tailwind の raw palette クラス(`bg-slate-50`、`text-emerald-600` 等)を**使わない**。`frontend/src/index.css` で定義した token だけを使う:
  - semantic token: `bg-background`, `text-foreground`, `bg-card`, `text-muted-foreground`, `text-destructive`, `text-success` 等
  - Status domain token: 提出結果の Status (AC/WA/TLE/MLE/RE/OLE/IE) の色は `text-status-ac`, `bg-status-wa` 等。Status の色はドメインの語彙であり、画面ごとに選ばない
- 現状は light mode のみ(issue #94)だが、色を必ず CSS variable 経由にすることで dark mode を後付けできる状態を保つ。
- UI コンポーネントは shadcn/ui(`frontend/src/components/ui/`)。shadcn CLI が生成したファイルは慣例上そのまま使ってよいが、カスタマイズする場合も token 経由で色を指定する。
