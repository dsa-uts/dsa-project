# Native macOS development with OrbStack Kubernetes

Development commands, editing, Codex, and host Playwright run on Apple Silicon macOS so browsers can access the application directly. Applications and PostgreSQL run on externally managed OrbStack Kubernetes; Linux CI keeps k3d. This supersedes the local k3s/VM and direct containerd import assumptions in ADRs 0005, 0012, 0013, and 0016, and the shared Linux browser environment in ADR 0018. Their Kubernetes, Kustomize, and deployed public HTTP interface decisions remain accepted.

Nix exposes native macOS packages/devShell and Linux-only image outputs. The dotfiles-managed Linux builder produces complete `buildLayeredImage` tar archives, which macOS loads through the OrbStack Docker context. Hash-derived image tags still drive rollouts. OrbStack shares Docker images with Kubernetes, so a registry and the old local k3s import path are unnecessary; CI retains Docker/k3d import. Linux production support is independent of retaining VM development.

`task cluster:setup` installs or upgrades the official Traefik chart using a repository-pinned version and shared values. This supersedes the blanket removal of Helm in ADR 0017 only for ingress infrastructure; application manifests remain Kustomize. CI disables k3d's bundled Traefik and installs the same chart. OrbStack and builder lifecycle management remain external, while daily `task deploy` builds, loads, applies, and waits for readiness without hot reload.

Development and E2E use `https://dsa.k8s.orb.local` and `https://dsa-e2e.k8s.orb.local`, separate namespaces and databases, and the cluster's default StorageClass. Secure `__Host-` session cookies require HTTPS on these custom domains; the initial HTTP URL proposal was revised after browser verification (localhost had been exempt). CI inherits the shared E2E overlay, overrides the ingress hostname, removes the local TLS annotation, and publishes HTTP on port 8080. Databases start fresh from existing seed; ordinary deploy preserves data, explicit reset/deletion owns data removal, and outage tests retain recovery behavior. Old VM deletion and data migration are outside this change.

macOS installs Chromium through the locked Playwright npm package into its standard OS cache. Linux retains the Nix browser package and Linux-only browser/font settings. Test sources are read directly from the working directory; static Nix E2E checks, codegen drift checks, normal/outage tests, and diagnostic artifacts remain. Production publication, GHCR delivery, and GitOps are deferred.

OrbStack manages local TLS certificates, while local Ingress annotations enable TLS routing on the shared `web` entrypoint. macOS Chromium uses the trusted OrbStack CA in Keychain. The pinned Nix Node build does not discover that user CA through its system-CA option, so the devShell exports only the public CA to the OS cache for `NODE_EXTRA_CA_CERTS`; certificate verification remains enabled. Sequential public HTTP requests and browser login cover transport reuse and Secure Cookie behavior.
